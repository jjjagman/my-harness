# 하네스 파이프라인

## 단계별 입출력

| 단계 | 기존 작업 | 입력 | 출력 |
|---|---|---|---|
| 1. 레퍼런스 수집·분석 | 1·2번 | PRD, 레퍼런스 | 출처가 포함된 레퍼런스와 공통 패턴 정리 |
| 2. 화면 구조 설계 | 3번 | PRD, 공통 패턴 | 화면 목록·구조 문서 |
| 3. 디자인 규칙 정의 | 4번 | 디자인 문서, 화면 구조 | 색·간격·타이포·컴포넌트 규칙 |
| 4. 피그마 화면 제작 | 5번 | 화면 구조, 디자인 규칙 | 핵심 화면 5종 |
| 5. 검토·전달 준비 | 6·7번 | 화면, 서비스 기준, 디자인 규칙 | 검토 결과와 개발자 전달용 산출물 |

## 필수 정보
- 단계 1: 모든 레퍼런스에 출처 URL과 참고 이유를 기록한다. 누락 건수는 0건이어야 한다.
- 단계 2: 모든 화면에 화면 ID와 PRD 근거를 기록한다. 누락 건수는 0건이어야 한다.
- 단계 4: 기록 목록, 차 기록 작성, 기록 상세, 내 취향 분석, 기록 항목 설정의 5종을 포함한다.

## 게이트 위치
- 기존 작업 2번의 컨펌은 단계 1 완료 후에 대응한다.
- 기존 작업 4번의 컨펌은 단계 3 완료 후에 대응한다.
- 기존 작업 6번의 컨펌은 단계 5의 검토 후, 전달용 산출물 확정 전에 대응한다.
- 각 게이트의 자동 판정과 사람 승인 방식은 R5에서 확정한다.

## 실패 시 복귀
- 레퍼런스 근거 부족: 단계 1로 복귀한다.
- 화면 또는 요구사항 누락: 단계 2로 복귀한다.
- 디자인 규칙 누락 또는 충돌: 단계 3으로 복귀한다.
- 정해진 규칙과 화면의 불일치: 단계 4로 복귀한다.
- 수정 후 영향을 받은 후속 단계와 검토를 다시 실행한다.

## 전달 범위
- 전달용 파일과 피그마 링크 준비까지 자동화한다.
- 실제 개발자에게 보내는 일은 디자이너가 한다.
