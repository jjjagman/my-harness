# 하네스 오케스트레이터

## 실행 환경
- Codex를 사용한다.
- 최종 실행 지침은 루트 AGENTS.md에 작성한다.

## 실행 순서
1. 단계 1: 레퍼런스 수집·분석
2. G1: 자동 검사
3. 단계 2: 화면 구조 설계
4. 단계 3: 디자인 규칙 정의
5. G2: 자동 검사
6. 단계 4: 피그마 화면 제작
7. 단계 5: 최종 검토
8. G3: 자동 검사 및 디자이너 승인
9. 개발자 전달 문서 확정

게이트가 실패 또는 보류이면 다음 단계로 넘어가지 않는다.
실제 개발자에게 보내는 일은 디자이너가 한다.

## 시작 전 확인
- 필수 컨텍스트 문서가 존재하는지 확인한다.
- 요청한 작업 범위와 필요한 도구의 접근 가능 여부를 확인한다.
- 피그마 편집 전 대상 파일과 페이지가 지정되어 있어야 한다.
- 필요한 정보가 누락되면 해당 작업을 보류하고 질문한다.

## 기준 문서

서비스 스토리는 판정 기준으로,
작업 스토리는 실제 작업 흐름의 근거로 사용한다.

## 충돌과 미확정 사항
- 문서가 충돌하면 해당 위치와 결정할 항목을 제시한다.
- 규칙이 미확정이면 관련 작업과 판정을 보류한다.
- 오케스트레이터는 임의로 기준을 변경하지 않는다.
- 입력 정보 확인은 G3의 최종 승인과 구분한다.

## 실행 관리
- 역할별 편집 권한은 r6-roles.md를 따른다.
- 게이트와 실패 시 복귀는 r5-gates.md를 따른다.
- 상태 기록, 이력 보관, 재개는 r4-artifacts.md를 따른다.
- 자연어 트리거는 r6-roles.md를 따른다.
- 스크립트가 읽는 수치·판정 규칙은 rules/design-rules.json을 참조한다.
