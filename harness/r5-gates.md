# 하네스 게이트

## 게이트 위치와 승인 방식
- G1: 레퍼런스 수집·분석 완료 후 자동 검사한다.
- G2: 화면 구조와 디자인 규칙 정의 완료 후 자동 검사한다.
- G3: 피그마 화면 제작과 최종 검토 후 자동 검사하고, 디자이너 본인이 승인한다.
- 사람 승인 지점은 G3의 1곳이다.
- story-work.md의 실제 작업 경험은 보존하며, 이 문서는 하네스에서 사용할 승인 방식을 정의한다.

## 자동 통과 조건

| 게이트 | 검사 대상 | 통과 조건 |
|---|---|---|
| G1 | 레퍼런스 | 1개 이상, 출처 URL·참고 이유 누락 0건 |
| G1 | 공통 패턴 | 각 패턴에 연결된 서로 다른 레퍼런스 2개 이상 |
| G2 | 화면 구조 | 필수 화면 5종 누락 0건, 화면 ID 중복 0건, PRD 근거 누락 0건 |
| G2 | 디자인 규칙 | 규칙 ID 중복 0건, 원문 근거 누락 0건, 미확정 값·원문 충돌 0건 |
| G3 | 피그마 화면 | 필수 화면별 실제 노드 연결 누락 0건, 검사용 데이터 추출 실패 0건 |
| G3 | 디자인 속성 | 검사 대상 속성의 허용 토큰 위반 0건 |
| G2·G3 | 서비스 위반 금지 조건 | 필수 입력 필드 집합이 차 이름 1개와 정확히 일치하고, 선택 항목의 표시·숨김 설정 누락 0건 |

- 필수 화면: 기록 목록, 차 기록 작성, 기록 상세, 내 취향 분석, 기록 항목 설정.
- 서비스 위반 금지 조건의 근거는 story-service.md다.
- G2는 화면 구조 문서를, G3는 피그마 추출 데이터를 검사한다.
- 디자인 단계의 검사는 화면 명세와 표현을 대상으로 한다. 실제 저장 동작은 구현 이후에 검증한다.
- 스크립트가 읽는 규칙은 rules/design-rules.json으로 통일한다.

## 판정 상태
- 필수 검사 실패 0건, 보류 0건이어야 자동 통과한다.
- 검사에 필요한 근거 데이터가 없으면 보류한다.
- 의미 판단이 필요한 원문 충돌 등을 자동으로 확인할 수 없으면 통과로 간주하지 않고 보류한다.

## 최종 사람 승인
디자이너 본인이 다음 항목을 확인한다.

- 손그림 표현의 자연스러움
- 참고 스타일과의 부합
- 시각적 가독성

자동 검사 통과와 위 3개 항목의 승인 완료가 모두 필요하다.
미승인 항목은 0개여야 한다.
승인은 검토한 산출물 버전에 연결해 기록한다.

## 실패·반려 시 복귀
- 레퍼런스 근거 부족: 단계 1로 복귀한다.
- 화면 또는 요구사항 누락: 단계 2로 복귀한다.
- 디자인 규칙 누락 또는 충돌: 단계 3으로 복귀한다.
- 정해진 규칙과 화면의 불일치: 단계 4로 복귀한다.
- 수정 후 영향을 받은 후속 단계와 검토를 다시 실행한다.
- 자동 수정은 게이트별 최대 2회로 제한한다.
- 2회 수정 후에도 통과하지 못하면 중단하고, 원인과 필요한 결정을 보고한다.
- 사람 반려 시 사유를 기록하고 해당 단계부터 수정한다.
- 변경된 산출물에 대한 이전 검사와 승인은 무효화한다.
